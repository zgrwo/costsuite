# 深度代码审查 Prompt

> 从最小审查（min）到最大审查（max）的分级模板。根据变更范围选择对应级别。

## 审查级别

| 级别 | 适用场景 | 维度数 |
|------|----------|--------|
| **Min** | 单文件小修复 | 3 |
| **Standard** | 功能迭代（≤5 文件） | 6 |
| **Max** | 发版前全量审查 | 10 |

---

## Min 审查（3 维度）

```
1. **正确性**：逻辑是否正确？边界条件是否覆盖？
2. **防御性**：null/空/NaN/越界是否有守卫？
3. **一致性**：与现有代码风格、命名、架构是否一致？
```

---

## Standard 审查（6 维度）

```
1. **正确性**：算法逻辑、边界条件
2. **防御性**：null/NaN/空集合守卫
3. **安全性**：SQL 参数化、路径验证
4. **一致性**：架构分层（UI→Service→Engine→Data）、命名规范
5. **性能**：BOM 展开效率、无不必要分配
6. **测试覆盖**：新增代码有对应测试？
```

---

## Max 审查（10 维度）

```
1. 算法正确性（BOM 展开、差异计算）
2. 防御编程（null 守卫、异常过滤器）
3. 安全（SQL 参数化、路径沙箱）
4. 架构合规（4 层单向、Engine 零依赖）
5. 文档一致性（api-reference 与代码一致）
6. 测试完备性（边界/退化输入覆盖）
7. 性能（10 万物料/100 万节点目标）
8. 错误处理（离线降级、资源清理）
9. 兼容性（net472 + Excel-DNA）
10. 工程规范（无死代码、命名一致）
```

---

## 审查后行动

| 发现级别 | 行动 |
|----------|------|
| P0 | 立即修复 |
| P1 | 本次修复 |
| P2 | 记录到改进计划 |
| P3 | 可选 |
